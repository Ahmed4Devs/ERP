# قواعد الحسابات الدائنة (الموردين) والقيود المحاسبية الصارمة

## نظرة عامة
تختص وحدة الحسابات الدائنة (A/P) بإدارة مستحقات الموردين، والتحقق من الفواتير، واحتساب ضريبة المدخلات المستردة، وصرف الدفعات وتسويتها. ووفقاً للمبادئ الأساسية لنظام تخطيط الموارد ERP، فإن جميع العمليات معزولة تماماً حسب المستأجر والشركة القانونية وتتم عبر عمليات ذرية متوازنة (Atomic Transactions).

---

## 1. الثوابت المحاسبية والقيود المزدوجة المتوازنة

### 1.1 إثبات فاتورة المورد (Vendor Bill Recognition)
عند ترحيل فاتورة المورد، يُنشئ النظام قيداً محاسبياً متوازناً وغير قابل للتعديل:

$$\sum \text{المدين} = \sum \text{الدائن}$$

- **مدين:** حساب المصروف (مثل `5100 المصروفات العمومية`، `5200 مصروفات البرمجيات وتكنولوجيا المعلومات`) بمبلغ المجموع الفرعي الخاضع للضريبة.
- **مدين:** ضريبة الاختبار المستردة (`1150 ضريبة الاختبار المستردة - مدخلات 10%`) بقيمة ضريبة المدخلات.
- **دائن:** حساب مراقبة الموردين (`2010 ذمم الموردين الدائنة A/P`) بكامل إجمالي الفاتورة.

```
مثال: فاتورة بقيمة 2,000 ريال مع ضريبة تجريبية 10% (200 ريال)
------------------------------------------------------------
من حـ/ 5200 مصروفات البرمجيات وتكنولوجيا المعلومات  2,000.00 ر.س (مدين)
من حـ/ 1150 ضريبة الاختبار المستردة (مدخلات 10%)       200.00 ر.س (مدين)
إلى حـ/ 2010 ذمم الموردين الدائنة (A/P)              2,200.00 ر.س (دائن)
```

### 1.2 تناظر ضريبة المدخلات مع ضريبة المخرجات
- **فواتير مبيعات وخدمات العملاء:** تُسجل كدائن في `2150 ضريبة الاختبار المستحقة` (Output Tax).
- **فواتير مشتريات الموردين:** تُسجل كمدين في `1150 ضريبة الاختبار المستردة` (Input Tax).
- صافي الالتزام الضريبي = رصيد حـ/ 2150 (دائن) - رصيد حـ/ 1150 (مدين).

### 1.3 سندات صرف الموردين وتخصيص الدفعات (Disbursements)
عند إصدار سند صرف للمورد:
- **مدين:** حساب مراقبة الموردين (`2010 ذمم الموردين الدائنة A/P`) بقيمة المبلغ المسدد.
- **دائن:** حساب البنك أو الصندوق (`1020 الحساب البنكي الجاري` أو `1010 الصندوق / الخزينة`) بقيمة المبلغ المسدد.

```
مثال: سداد دفعة للمورد بقيمة 1,000 ريال عبر تحويل بنكي
------------------------------------------------------------
من حـ/ 2010 ذمم الموردين الدائنة (A/P)              1,000.00 ر.س (مدين)
إلى حـ/ 1020 الحساب البنكي الجاري                   1,000.00 ر.س (دائن)
```

## 2. آلة الحالات للمستندات التجارية (State Machines)

### 2.1 دورة حياة أمر الشراء (Purchase Order)
```
[مسودة Draft] ---> (اعتماد Approve) ---> [معتمد Approved] ---> (إصدار الفاتورة) ---> [مفوتر Billed]
      |                                      |
      +--------------> [ملغى Cancelled] <----+
```

### 2.2 دورة حياة فاتورة المورد (Vendor Bill)
```
[مسودة Draft] ---> (ترحيل Post) ---> [مرحلة Posted]
                                           |
                 +-------------------------+-------------------------+
                 |                                                   |
         (سداد جزئي Partial)                                 (سداد كامل Full)
                 v                                                   v
       [مدفوعة جزئياً] ---> (سداد المتبقي) --------------> [مدفوعة بالكامل Paid]
```

### 2.3 قواعد التزامن وحماية التكرار (Concurrency & Idempotency)
- منع إعادة ترحيل أي فاتورة مرحلة سابقاً؛ محاولة الترحيل المكرر تُرجع استثناء `PostingConflictException` مع رمز الحالة HTTP 409.
- الفترات المالية المقفلة تمنع منعاً باتاً ترحيل أي فواتير أو دفعات.

## 3. محرك تقرير أعمار ديون الموردين (AP Aging Engine)
يقوم محرك التقرير بحساب مستحقات الموردين وتصنيفها في فترات زمنية دقيقة استناداً إلى تاريخ الاستحقاق مقارنة بتاريخ التقرير المستهدف ($T_{\text{asOf}}$):

1. **جاري (0 إلى 30 يوماً):** تاريخ الاستحقاق يقع ضمن 30 يوماً من تاريخ التقرير.
2. **من 31 إلى 60 يوماً:** مستحق منذ 31 إلى 60 يوماً مضت.
3. **من 61 إلى 90 يوماً:** مستحق منذ 61 إلى 90 يوماً مضت.
4. **أكثر من 90 يوماً:** مستحق منذ أكثر من 90 يوماً مضت.

تتم كافة العمليات الحسابية بدقة 6 خانات عشرية `NUMERIC(24,6)` عبر مكتبة `bcmath` لضمان الدقة المالية المطلقة.
