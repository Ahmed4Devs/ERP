# تقرير التحقق الأمني وفق معيار OWASP ASVS 4.0

تحدد هذه الوثيقة ضوابط الأمان، وآليات معالجة نموذج التهديدات، وأدلة التحقق الفعلي وفق معيار ASVS 4.0 لتطبيق تخطيط الموارد المؤسسية (ERP).

---

## 1. نظرة عامة على الهيكلية الأمنية ونموذج التهديدات

يعتمد النظام مبدأ "الدفاع في العمق" (Defense-in-Depth) عبر طبقات متعددة:
- **تحديد نطاق المستأجر والكيان القانوني**: يحتوي كل جدول علائقي يضم بيانات تشغيلية أو مالية على معرّف المستأجر `tenant_id`، ومعرّف الشركة `company_id`. وتمنع النطاقات العامة في Eloquent وحراس وحدات التحكم أي تداخل بين المستأجرين.
- **الحصانة المالية للقيود (Immutability)**: تُعد قيود اليومية المرحلة، وبنود الفواتير، وحركات المخزون سجلات غير قابلة للتعديل أو الحذف المباشر؛ وأي تصحيح مالي يستلزم قيداً عكسياً أو إشعاراً دائناً معتمداً.
- **الدقة الرياضية الصارمة**: تستخدم كافة العمليات الحسابية للأموال والمخزون نوع البيانات `NUMERIC(24,6)` ودوال `bcmath` في PHP، مما يمنع ثغرات الفواصل العائمة وأخطاء التقريب الحسابي.

## 3. أدلة اختبارات العزل السلبية

تثبت اختبارات الأمان الآلية (`tests/Feature/Release/SecurityComplianceTest.php` و `tests/Feature/Platform/TenancyIsolationTest.php`) بشكل قاطع ما يلي:
1. **الوصول غير المصرح به**: يتم تحويل الطلبات غير المصادق عليها إلى صفحة تسجيل الدخول `/login`.
2. **منع التداخل بين المستأجرين**: عند محاولة مستخدم ينتمي للمستأجر (ب) الوصول لموارد المستأجر (أ) (كنقاط البيع، أو المستخلصات، أو أوامر الإنتاج)، يرد النظام برمز المنع `403 Forbidden` أو عدم الوجود `404 Not Found`.
3. **حدود الشركات**: لا يمكن لأي مستخدم التبديل إلى شركة لا تتبع للمستأجر المصرح له به.
4. **منع البيع السالب للمخزون**: تطلق محاولات البيع التي تتجاوز الرصيد المتاح استثناء `InsufficientStockException` لمنع نشوء كميات سالبة.
