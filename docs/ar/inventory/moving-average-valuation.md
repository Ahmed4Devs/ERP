# تقييم المخزون المستمر بالمتوسط المرجح المتحرك (Moving Weighted-Average)

## نظرة عامة
يطبق النظام محرك تقييم مخزون مستمر ودائم يعتمد على طريقة **المتوسط المرجح المتحرك** (Perpetual Moving Weighted-Average Costing) لجميع البضائع القابلة للتخزين. في ظل هذه الطريقة، يعاد حساب تكلفة الوحدة الواحدة بشكل ديناميكي فوري عند كل عملية استلام بضاعة جديدة في المستودع.

أما حركات الصرف والبيع والمناقلات الصادرة، فيتم تسعيرها بتكلفة المتوسط المرجح القائمة دون أي تغيير أو تعديل على تكلفة وحدة الصنف.

---

## 1. الرياضيات والمعادلات المحاسبية

### أ. حركات الاستلام والتوريد الواردة (إعادة احتساب التكلفة)
عند استلام كمية بضاعة واردة $Q_{\text{in}}$ بتكلفة شراء فعلية للوحدة $C_{\text{in}}$:

$$V_{\text{new}} = V_{\text{old}} + (Q_{\text{in}} \times C_{\text{in}})$$

$$Q_{\text{new}} = Q_{\text{old}} + Q_{\text{in}}$$

$$C_{\text{new}} = \frac{V_{\text{new}}}{Q_{\text{new}}}$$

حيث:
- $Q_{\text{old}}$: كمية الرصيد المخزني السابقة في المستودع
- $C_{\text{old}}$: تكلفة المتوسط المرجح السابقة للوحدة
- $V_{\text{old}} = Q_{\text{old}} \times C_{\text{old}}$: القيمة الإجمالية السابقة للمخزون
- $Q_{\text{new}}$: كمية الرصيد المخزني الجديدة بعد التوريد
- $C_{\text{new}}$: تكلفة المتوسط المرجح الجديدة للوحدة

### ب. حركات الصرف والبيع الصادرة (ثبات التكلفة)
عند صرف أو بيع كمية بضاعة $Q_{\text{out}}$ من المستودع:
- تكون تكلفة الوحدة المصروفة مساوية تماماً لتكلفة المتوسط المرجح القائمة: $C_{\text{issue}} = C_{\text{old}}$.
- إجمالي قيمة التكلفة المصروفة: $V_{\text{out}} = Q_{\text{out}} \times C_{\text{old}}$.
- الكمية المتبقية: $Q_{\text{new}} = Q_{\text{old}} - Q_{\text{out}}$.
- القيمة المتبقية: $V_{\text{new}} = Q_{\text{new}} \times C_{\text{old}}$.
- **قاعدة ذهبية:** لا تتغير تكلفة وحدة المخزون إطلاقاً عند حركات الصرف أو البيع.

## 2. الدقة العددية ومنع الأرصدة السالبة

1. **دقة حسابية متناهية (6 خانات عشرية):**
   يتم تخزين الكميات وتكاليف الوحدات والقيم كحقول `NUMERIC(24,6)`، ويتم إجراؤها باستخدام مكتبة `bcmath` بدقة مطلقة لمنع أي فروقات تقريب أو تشوهات ناتجة عن الفواصل العائمة.

2. **منع الأرصدة السالبة للمخزون (Non-Negative Stock Invariant):**
   المخزون السالب يشوه معادلات التكلفة ويخالف معايير المحاسبة الدولية IFRS وGAAP.
   - **على مستوى قاعدة البيانات:** قيود فحص قاطعة في PostgreSQL:
     ```sql
     ALTER TABLE inventory_levels ADD CONSTRAINT chk_inventory_levels_non_negative_stock CHECK (quantity_on_hand >= 0);
     ALTER TABLE inventory_levels ADD CONSTRAINT chk_inventory_levels_non_negative_reserved CHECK (quantity_reserved >= 0);
     ALTER TABLE inventory_levels ADD CONSTRAINT chk_inventory_levels_non_negative_cost CHECK (moving_average_cost >= 0);
     ```
   - **على مستوى محرك التطبيق:** يفحص `InventoryCostingEngine` الكمية المتاحة عبر `lockForUpdate()` ويرمي استثناء `InsufficientStockException` في حال عدم كفاية المخزون قبل إجراء أي قيد.

## 3. المطابقة التامة مع الأستاذ العام (GL Reconciliation)

يتم مطابقة الأستاذ المساعد للمخزون فورياً مع حساب الرقابة في الأستاذ العام `1300 مخزون بضاعة بالمستودع`:

$$\sum_{\text{جميع الأصناف}} (\text{الكمية المتوفرة} \times \text{تكلفة المتوسط المرجح}) = \text{رصيد حساب 1300 في الأستاذ العام}$$

ويتيح تقرير تقييم المخزون المالي التحقق اللحظي من تطابق الرصيدين مع تأكيد انعدام أي فروقات (Variance = 0.00).
